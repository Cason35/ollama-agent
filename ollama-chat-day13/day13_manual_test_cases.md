## 二、页面与基础交互（不依赖模型语义）

| ID | 操作 | 预期 |
|----|------|------|
| UI-1 | 初始状态：未发送任何消息 | 对话区显示灰色提示「聊天记录会显示在这里」；右侧 Memory 显示 `shortTerm: 0` / `items: 0` 或等价计数 |
| UI-2 | 输入框为空时点「发送」 | 无请求、无新气泡 |
| UI-3 | 输入任意文本发送后 | 用户气泡出现在右侧样式（深色条）；加载中按钮文案为「处理中...」，输入框与 Workflow 勾选框禁用 |
| UI-4 | 响应返回后 | 加载结束；列表平滑滚到底部；输入框恢复可编辑 |
| UI-5 | 输入超过视觉长度（最多 2000 字符） | 输入框 `maxLength` 生效（前端限制） |

## 三、普通模式（**不勾选**「Workflow 多步骤模式」）

路由依赖模型输出 JSON，若结果不符合预期，可多试 1～2 次或查看终端 `[Agent]` 日志。

### 3.1 闲聊 `chat`

| ID | 建议输入（示例） | 预期（要点） |
|----|------------------|--------------|
| CHAT-1 | `你好，简单介绍一下你自己` | 返回类型表现为 **助手普通气泡**（灰底「助手」）；右侧 `memory` 可能随规则略有更新 |
| CHAT-2 | `1+1等于几` | 同上，普通文本回复 |

### 3.2 天气 `weather`（Open-Meteo，仅支持 **北京、上海**）

| ID | 建议输入 | 预期 |
|----|----------|------|
| W-1 | `北京今天天气怎么样` | **天气卡片**（浅蓝边框）；关键词含「北京」；正文含温度（如 `°C`）；`memory` 正常带回 |
| W-2 | `查一下上海的气温` | 同上，上海 |
| W-3 | `深圳天气如何` | 助手侧应提示 **不支持该城市**（文案中含「北京、上海」类说明，与 `realWeather` 兜底一致） |

### 3.3 总结 `summary`

| ID | 建议输入 | 预期 |
|----|----------|------|
| S-1 | 先发 2～3 轮无关闲聊，再发：`请把上面的对话总结成要点` | **总结卡片**（琥珀色标题「总结」）；条目多为 `- ` 列表风格；含「结论」「下一步」类尾部（模型尽力而为） |

### 3.4 待办 `todo`

| ID | 建议输入 | 预期 |
|----|----------|------|
| T-1 | `帮我列一个本周学习 Agent 开发的待办清单` | **待办卡片**（绿色「待办计划」）；多条 `task` + 只读 checkbox |
| T-2 | `给我明天的任务清单，至少三项` | 同上 |

### 3.5 规则记忆 + Memory 面板

| ID | 建议输入 | 预期 |
|----|----------|------|
| M-1 | `我叫张三，正在学习 Next.js` | 右侧 **items** 增加条目；命中自我介绍类规则时，条目左侧 **`high`** 样式（琥珀左边框） |
| M-2 | `哈哈随便聊聊` | 可为 **`low`** 或闲聊类记忆（依模型与规则合并结果而定） |
| M-3 | 发送后观察 `shortTerm` 计数 | 随对话轮数变化；长期多条对话后仍应保持页面可用（后端有窗口与压缩逻辑） |

### 3.6 延续话术 `resolveContinuationAction`

| ID | 操作建议 | 预期 |
|----|----------|------|
| C-1 | 先发：`帮我做一个下月的学习计划并发待办`，待返回待办后，再发：`继续刚才的任务，再细化一下` | 第二轮倾向仍走 **待办或相关工具**，而非空闲聊（允许模型波动，对比日志 `action`） |
| C-2 | 在曾有「总结」语境的记忆下，发：`继续总结一下上文要点` | 倾向 **summary** |

## 四、Workflow 模式（**勾选**「Workflow 多步骤模式」）

| ID | 建议输入 | 预期 |
|----|----------|------|
| WF-1 | `规划明天学习任务：先查北京天气，再根据天气帮我总结注意事项，最后生成待办清单` | **紫色 Workflow 卡片**；标题含 goal；步骤列表含 `[chat|summary|todo|weather]`；每步有状态图标（✅/❌/⏳/⏸）；底部 **最终结果** 有汇总段落 |
| WF-2 | `我想去上海出差，查天气并列出我需要准备的清单` | 至少一步 **weather（上海）** + **todo** 或 **chat**；步骤顺序由 Planner 决定 |
| WF-3 | （可选）停掉 Ollama 再发 WF-1 | Planner 失败时应退化（例如单步 chat）；或步骤中报错；**不应整页白屏**；顶部或气泡内有可读错误 |

**服务端日志**：终端应出现 `[Workflow] start` / `step` / `done` 及 `[Workflow] output:`（便于对齐每步输出）。

## 五、异常与 API 直接探测

### 5.1 HTTP 层

| ID | 操作 | 预期 |
|----|------|------|
| ERR-1 | Ollama 未启动时发送任意消息 | HTTP 500 或 JSON `error`；页面 **红色错误文案** + 助手气泡提示（非静默失败） |
| ERR-2 | 使用 curl / REST 客户端：`POST /api/chat`，body 为 `{}` 或 `{ "messages": [] }` | **400**，body 含 `messages is required` |

**curl 示例（PowerShell 外可自行换引号）**：

```bash
curl -s -X POST http://localhost:3000/api/chat ^
  -H "Content-Type: application/json" ^
  -d "{\"messages\":[]}"
```

### 5.2 网络断开（可选）

| ID | 操作 | 预期 |
|----|------|------|
| NET-1 | 开发中关掉 Wi‑Fi 再发送 | 顶部提示「网络异常…」类文案；助手气泡含 `Network error`（与 `page.tsx` catch 分支一致） |
