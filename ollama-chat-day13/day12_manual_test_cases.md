# 第12天手动验收用例

在 Day12 聊天页面按顺序发送消息即可验证「Memory 参与决策链」相关能力。

---

## 用例 A：记忆参与路由 +「继续」类省略语 → Todo

**目的**：高优先级记忆里有目标/任务语境时，「继续…」应倾向路由到 **todo**，而不是闲聊。

1. 先发一条建立身份与目标（应沉淀为 **high**）：

   `我是前端工程师，最近三个月的目标是转型做 Agent 应用，请先帮我列一个学习计划。`

2. 等返回待办卡片后，再发（刻意简短、省略主语）：

   `继续刚才那个任务，按上次计划再细化一步。`

**预期**：第二轮仍出现 **待办计划**（含与你的身份/目标相关的条目），而不是普通闲聊气泡。

---

## 用例 B：「继续」→ Summary（与记忆语义一致）

**目的**：用户明确要「归纳/要点」时，应走 **summary**。

1. `我想总结一下我们刚才聊的重点，结论和下一步都要。`

   （若上一轮主要是聊天，可先随便聊 2～3 句再发这句。）

2. 或先发：`帮我归纳三点：目标、风险、下一步。`

   再发：`接着上文继续总结，补充遗漏点。`

**预期**：返回 **总结** 卡片（琥珀色），且文案里尽量贴合上下文；第二轮「接着上文」仍应是总结而非 todo。

---

## 用例 C：Todo 个性化（Memory 参与工具执行）

**目的**：同样说「列待办」，有记忆时应比「通用三条空话」更贴用户。

1. `我叫小王，准备转行做后端，正在学 Go 和数据库。请帮我列本周待办。`

2. 看三条任务里是否出现 **Go / 数据库 / 转行 / 学习路径** 等你刚说的信息。

**预期**：待办明显带个人信息；右侧 Debug 里应能看到对应 **high** 条目（如身份、目标）。

---

## 用例 D：二次压缩 + 长度可控（需多轮撑长记忆）

**目的**：长期记忆字符变多时触发 **二次压缩**，条目数被压到约 **≤5**，重复减少。

1. 连续发多条「带事实」的用户消息（不必一次很长），例如：

   - `我的目标是三个月内上线一个 Demo。`
   - `我偏好早上写代码，晚上看文档。`
   - `我不想接外包，只想做产品向。`

   再故意重复类似句子 3～4 次（略改表述）。

2. 每发几条看一眼右侧 **Memory Debug**：`items` 是否仍 **≤5** 左右、总字数是否被压住，重复是否变少。

**预期**：`items` 不会无限涨；在体量变大后出现「合并后的少量核心事实」；**high** 相关（目标/偏好）应尽量保留。

---

## 用例 E：权重可视化（high / low）

**目的**：确认 **规则抽取** 与 **模型标注** 能分出 high/low。

1. 发：`哈哈今天随便聊聊，天气真好。`（偏闲聊）

2. 再发：`我是产品经理，目标是年底掌握 Agent 编排。`

**预期**：右侧列表里，第二条相关条目多为 **high**；闲聊句若被记入记忆，多为 **low**（是否记入取决于摘要/规则，以界面为准）。

---

## 快速对照清单

| 现象 | 对应 Day12 |
|------|------------|
| 「继续刚才…」仍能出待办/总结 | 记忆参与路由 + continuation |
| 待办里出现你的名字/目标/技术栈 | 工具执行带 memory |
| 多轮后记忆条目仍很少、不啰嗦 | 二次压缩 |
| 右侧有 high/low 标签 | 记忆权重 |

## 运行前提醒

- 本地需启动 Ollama，且 `app/api/chat/route.ts` 中的模型名称需与本机已拉取的模型一致（默认 `qwen2.5:14b`）。
- 在项目目录执行 `npm run dev` 后打开首页进行上述操作。
